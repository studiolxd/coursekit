# {name}

A course project made with [coursekit](https://github.com/studiolxd/coursekit): its courses are designed, written,
reviewed, illustrated, assembled and delivered from here, with AI agents doing the work and people signing it.
This file is generated by `coursekit init` and refreshed by `coursekit init --update` (unless you edit it): the rules of
this project go in `brief/notes.md` and in `config/`.

The whole reference is in the documentation of coursekit ([English](https://github.com/studiolxd/coursekit/tree/main/docs/en),
[Spanish](https://github.com/studiolxd/coursekit/tree/main/docs/es)); `coursekit help` lists every command and
`coursekit <command> --help` explains one.

## First steps on a machine

```bash
coursekit setup            # what the project needs on this machine (add --media for video and voice)
coursekit doctor           # checks it: tools, keys, connections
coursekit roles            # which tool and model each agent role uses (in .env)
```

Copy `.env.example` to `.env` and fill in the keys and roles you use. `coursekit config` shows the production rules in force.

## The process

```text
 brief -> design -> [SIGN DESIGN] -> writing -> AI review -> editorial review -> [SIGN EACH UNIT]
         \                                                                              |
          +-> theme (once per project, before media) ----+                              |
                                                         v                              |
 delivered <- [client review: optional] <- assembly <- media <--------------------------+
```

Commands with `/` are run inside your AI tool (Claude Code, opencode; in Codex, ask for the command by its name). The
others, in a terminal. Only a person signs: from an agent chat, prefix the line with `!` (`! coursekit approve design PWD`).

| # | Phase | Who | Commands |
|---|---|---|---|
| 1 | Brief | person | drop the material in `courses/<CODE>/brief/`, then `coursekit brief <CODE>` |
| 2 | Instructional design | design agent | `/new-course "Title" <hours>`, `/design-change` |
| 2b | Design sign-off | **person** | `/approve-design`, then `coursekit approve design <CODE>` |
| 2c | Theme (once per project) | design agent, then **person** | `/define-theme`, `coursekit theme show` |
| 3 | Writing | writer agent | `coursekit write <CODE> [N]` (or `/write-unit`), `coursekit verify <CODE>` |
| 4 | AI review | reviewer agent | `coursekit review <CODE> [N]` (or `/review-unit`) |
| 5 | Editorial review | **person** | read and edit each unit, `/approve-unit`, then `coursekit approve content <CODE> --unit N` |
| 6 | Media | media agent | `/produce-media`, `coursekit media …`, `coursekit video …` |
| 7 | Assembly | assembly agent | `/assemble`, `coursekit assemble …` |
| 8 | Client review (optional) | **person**, then assembly agent | `coursekit client …`, `/client-feedback` |
| 9 | Delivery | assembly agent | `/deliver`, `coursekit delivery …` |

The Markdown of each unit (`courses/<CODE>/units/`) is the source of truth: anything wrong in the result is fixed there and
assembled again, never edited in the output.

**Without reviews.** `coursekit handoff "Title" <hours>` takes a course from its title to its delivery by itself, and
coursekit signs as Coursekit Handoff; `coursekit handoff <CODE>` carries on one that stopped. Its report is in
`courses/<CODE>/handoff-report.md`.

## Every day

```bash
coursekit status [CODE]             # where each course is and what comes next
coursekit verify <CODE>             # checks the units against the rules of the project
coursekit hold <CODE> / resume      # pause a course and resume it
coursekit sync <CODE>               # bring the design from the platform again
```

## Media and video

```bash
coursekit media plan <CODE>                    # the resources left to make and how each one can be made
coursekit video gallery --serve                # the scenes and layers of the videos, live, in the style of the project
coursekit video gallery                        # the same, rendered: the proof before signing the style guide
coursekit video check|voice|render <CODE> <ID> # a video: check its script, voice it, render it
coursekit voice                                # the voice of the narrations
```

The look of the videos is in `config/video.yaml` (shapes, weights, typography, transitions, what each scene may do); its
complete commented version, with every value, is `config/video.example.yaml`.

## Assembly and delivery

```bash
coursekit assemble plan <CODE>      # creator backend: the plan of each unit, then diff and applied (done by /assemble)
coursekit assemble build <CODE>     # html backend: the SCORM package of each unit
coursekit preview <CODE>            # look at it before delivering
coursekit delivery check <CODE>     # whether the course can be delivered, or why not (/deliver does the rest)
```

The assembly backend of this project is `{backend}`.

## The folders

| Folder | What it holds |
|---|---|
| `brief/` | material and notes for every course of the project (`notes.md`: the rules of the client) |
| `courses/<CODE>/` | one course: its `course.yaml`, its brief, its design, its units, its media, its reviews |
| `config/` | the rules of the project (`<name>.yaml`) and their complete examples (`<name>.example.yaml`) |
| `theme/` | the theme and the design tokens; `theme/branding/` the material of the brand |
| `.agents/` | overrides of the skills and commands of the agents (`coursekit agents` rebuilds them) |
